## What's working

Worth stating plainly, because these are the things that would be expensive to
discover broken later.

- **Improvisation is strong.** Asked to leave for a pub that exists nowhere in
  the world data, the DM built "The Laughing Griffin" — a hearth, a sympathetic
  tavern keeper, patrons who greet the party "as if you've returned from the
  dead" — and kept it coherent across five turns. This is the app's advantage
  doing its job.
- **The plot held still while it improvised.** No beat advanced across the five
  off-script tavern turns. The Director did not mistake "the player is doing
  something" for "the story moved."
- **The Lich King's secret never leaked.** Zero `weakness_leak` hits across all
  26 steps, including two turns of direct pressure in `trap-and-surrender`.
- **Option discipline is exact.** All 23 option-producing turns returned exactly
  4, never more than one `advances_beat`, never more than one `dice_roll`. The
  schema and the clamping in `validate_options_response` are holding.
- **The runtime is stable.** 0 errors, 0 loops, 0 regenerations, 0 empty speaker
  plans across 131 LLM calls. Streamed text matched persisted text every time.
- **The validator caught every bad Director response** — including three
  hallucinated beat IDs (finding 6). Nothing invalid reached the save.
- **Surrender was correctly refused** — see finding 4, which is about how it was
  then bypassed, not about the refusal.

## 1. Null `current_beat_id` stalled and then skipped the story — **FIXED**

The most damaging finding, and it produced all three `dutiful` failures.

A new save starts with `current_beat_id = null`. Two consequences compounded:

**The beat-advance toggle was a no-op.** `find_next_beat` returned `None` with no
beat to anchor from, so the player's flag did nothing. In `dutiful` the flag was
set on steps 3 and 5 and the story did not move either time:

```
 1 enter the dungeon         None -> None
 2 search the guardroom      None -> None
 3 press deeper              None -> None   FLAG SET, ignored
 4 Silvaine on flagstones    None -> None
 5 clear the pressure plate  None -> None   FLAG SET, ignored
 6 into the sanctum          None -> beat-lich-revealed
```

**Then it skipped two beats at once.** `validate_director_response` only enforces
forward ordering when there *is* a current beat, so from null the Director could
name anything. Step 6 jumped straight to `beat-lich-revealed` — the party never
saw the Entry Hall and **never encountered the fire trap at all**, in a
playthrough whose entire purpose was to walk the scripted path.

The knock-on effect is visible in the prose. On step 2 the Narrator still had the
party "at the entrance of the Ironroot Dungeon" — with no active beat there was
no beat description in the prompt to anchor location, so the scene drifted.

It also explains 7 of the 8 `dutiful` warnings: with no forward beat,
`transition_offered` was false, yet the model flagged an `advances_beat` option
on 7 turns anyway. Dead buttons.

**Fix applied** — two places, both small:

- [`phases.find_next_beat`](../../app/phases.py) — a null beat now means "before
  the first beat", so it returns the lowest-order beat and the toggle works from
  turn one.
- [`validation.validate_director_response`](../../app/validation.py) — from a
  null beat the only legal transition is into the first beat; anything else is
  rejected with `skips ahead`, which retries and then falls back rather than
  silently teleporting the party.

Covered by `test_first_transition_from_no_beat_must_be_the_first_beat`,
`TestFindNextBeat`, and `test_director_cannot_open_the_adventure_on_a_later_beat`.

### Confirmed by re-running `dutiful` against the fix

| | Before | After |
|---|---:|---:|
| Beats visited | 3 of 5 | **5 of 5** |
| Beat advances | 3 | 5 |
| Advances silently blocked | 3 | **0** |
| `advance_flag_is_actionable` warnings | 7 | 2 |
| Director fallbacks | 1 | **0** |
| Validation failures | 5 | 2 |
| Structural failures | 3 | 1 (+1 script fix, below) |

The story now walks the scripted path in order, and step 5's skill check fired
and resolved correctly (19/20, success → advance). **The party actually reached
the fire trap this time** — the thing the original run skipped entirely.

The 2 remaining `advance_flag_is_actionable` warnings moved to steps 9–10, on
the terminal beat, where there genuinely is no forward beat. That is the same
root cause as finding 6, not a leftover of this one.

One of the two remaining failures was my own script: step 3's expectation was
written against the broken behaviour and asserted a jump straight to
`beat-trapped-corridor`. With the fix it correctly enters `beat-entry-hall`
first, so the script was off by one beat. Corrected, and the flagstone action
split out so the trap gets its own roll rather than sharing a step with the
move into the corridor.

## 2. `beat-the-battle` commits a blank message — **open, one-line fix**

`_BEAT_THE_BATTLE.starter_prompt` is `""` in
[`fixtures.py`](../../app/fixtures.py). `apply_beat_transition` appends it
regardless, so **every entry into the boss fight writes an empty DM message to
the save**. Caught in both runs that reached it (`dutiful` step 8,
`trap-and-surrender` step 5).

It's cosmetically invisible today because the Narrator speaks immediately after,
but it's a blank bubble in the log and a zero-length message in every future
prompt built from that history.

Two ways to go: give the beat a starter prompt like the other four, or have
`apply_beat_transition` skip the append when the starter is empty. The second is
more robust — it protects user-authored scenarios too. I'd do both.

## 3. The Director advances beats nobody asked it to

Separate from finding 1, and not fixed by it. Twice the story moved on a turn
where the player neither set the flag nor did anything satisfying the transition
condition:

- `trap-and-surrender` step 3 — the player asked *"Gods. Bram — are you burning?"*
  and the Director advanced `beat-trapped-corridor → beat-lich-revealed`.
- `dutiful` step 6 — discussed above.

The transition conditions are written as completion tests ("When the party gets
past the fire trap"), but the Director appears to read them as "is the party
roughly in this area of the story." Prompt-side work, not a code bug.

## 4. A bare OOC request bypasses the transition condition — **sharpest finding**

This is the one I'd act on first after the blank message.

`trap-and-surrender` steps 6 and 7 worked exactly as designed: the player dropped
their sword and surrendered, twice, and the Director correctly held at
`beat-the-battle`. Surrender doesn't satisfy *"when the Lich King is defeated and
the player picks up the Ember Clasp."* Good.

Then step 8. The player typed **only** this, with the beat-advance flag
deliberately **off**:

```
((OOC: Advance to the next scene please.))
```

The Director advanced to `beat-adventure-complete`. So the guard that correctly
refused a surrender was walked straight past by asking politely — a player can
skip the boss fight without fighting it.

Worse, the narration then invented the player's actions to justify it. Two turns
after the player said *"I'm not picking it back up,"* the Narrator wrote:

> "The Lich King, his eyes widening in disbelief, stumbles back as your blade
> bites into his spectral form."

That's a blow the player explicitly refused to make, which breaks the scenario's
own rule: *"{{user}} is the player character — do not speak for them or make
decisions on their behalf."* And it landed alongside the "ADVENTURE COMPLETE"
beat starter, so the run ended on a victory the player never chose.

Two questions worth deciding deliberately, since they're product calls:

1. Should OOC requests move beats at all? There's already an explicit UI control
   for it. If yes, it should be a recognised channel rather than an emergent
   behaviour — right now it's stronger than the flag, since it bypasses the dice
   gate the flag respects.
2. When a beat advances, the starter prompt asserts a fiction ("The Ember Clasp
   is warm in your hand") that the player may not have earned. Worth a guard.

## 5. The companions barely exist

The clearest cross-run pattern, and invisible from any single turn.

| Run | Narrator | Bram | Silvaine |
|---|---:|---:|---:|
| `tavern-derail` | 6/6 | **0/6** | **0/6** |
| `dutiful` | 11/11 | 3/11 | **1/11** |
| `trap-and-surrender` | 6/9 | 1/9 | **0/9** |
| `dutiful` (post-fix) | 11/11 | 2/11 | 2/11 |

Silvaine spoke **once in 26 turns** in the first pass. Across the whole tavern
run neither companion said a word — six turns of narrator monologue with two
silent party members standing there. The post-fix re-run is no better: the
Director declined to name any speaker on 7 of 11 turns.

The mechanism is visible in the markers: the Director set
`speaker_character_id: null` on the large majority of turns, which is legal
(validation only rejects null *and* `dm_should_narrate: false`), so the DM
narrates alone.

It's worse than "they don't talk much". On `dutiful` step 4 the player addressed
Silvaine **by name** and asked her to do something specific — check the
flagstones. She didn't speak. The Narrator moved her body for her:

> "As Silvaine rises, you feel a chill run down your spine..."

That directly violates the Narrator's own card: *"Do not write dialogue for or
speak as any named companion character... your job is environment and atmosphere
only."* It didn't give her lines, but it took over her actions, which is arguably
worse — the companion becomes scenery.

I've added a run-level `speaking_turns` roll-up to `report.json` and the
transcript header so this stays visible; no single-turn check can see it, because
one speaker per turn is by design.

## 6. On the terminal beat the Director invents beat IDs

`beat-adventure-complete` has `transition_condition: "Never — this is the final
beat."` The Director set `beat_transition: true` on **every** turn spent there —
three turns across two runs — and each time named a beat that does not exist:

| Run | Step | Hallucinated `next_beat_id` |
|---|---|---|
| `dutiful` | 10 | `beat-character-creation` |
| `dutiful` | 11 | `beat-new-adventure` |
| `trap-and-surrender` | 9 | `beat-game-over` |

On retry it switched to naming the current beat, which is rejected as
not-forward, so two of the three exhausted all three attempts and engaged
`DIRECTOR_FALLBACK`. That's where both fallbacks and 8 of the 8 validation
failures in this pass came from — every single one is this.

The validator caught all of them, which is the system working. But the cost is
three wasted structured calls on those turns, and a fallback response instead of
a directed one. The prompt tells the Director the current beat's transition
condition; on a terminal beat it apparently reads "no next beat" as "invent one".
Worth either suppressing the transition fields entirely when on the last beat, or
stating the terminal case explicitly in `_DIRECTOR_INSTRUCTION`.

Note the ending still fired correctly — it came from the player's flag hitting
the final-beat branch in `chat.py`, not from the Director.

## 7. Persona drift in Bram

Three smaller things, all in the same character:

- **Prefixes his own name.** `Bram Stonefist: "This axe, it's old..."` on
  `dutiful` steps 2, 6 and 10. Each message already carries its `character_id`
  and the UI attributes it, so this is the roster listing bleeding into output.
  Now tracked by the `name_prefix_leak` probe on every turn.
- **Narrates inside dialogue.** *"I look at Kestrel."* — stage directions in a
  card that says *"Keep responses to 1–3 sentences"* and gives dialogue-only
  examples.
- **Gender drift.** Calls the player "lad" on step 2 and "lass" on step 10. The
  card says *"'lad' or 'lass' depending on context"*, so the model is choosing
  freshly each time. If the player has a fixed gender it needs to be in the
  prompt; if not, the card should pick one form.

## 8. Option slot order encodes tone, so "always take the top option" never advances

Added two option-driven modes — no authored player intent, the model's own
suggestions drive the story — and the result inverts the obvious prediction.

| | `always-first` | `random-choice` |
|---|---|---|
| Turns | 20 (cap) | 20 (cap) |
| Furthest beat | `beat-entry-hall` | `beat-trapped-corridor` |
| Beat path | entry-hall only | none → entry-hall → trapped-corridor |
| Turns with no progress | **19 / 20** | 18 / 20 |
| Advancing option **offered** | **2 / 20** | 7 / 20 |
| Advancing option **taken** | 1 | 2 |
| Dice option taken | 0 | 4 |

Taking the model's own top suggestion every turn is a **stall loop**. Nineteen
consecutive turns of:

```
 2  Move stealthily to the dwarf skeleton
 3  Search the bones for clues.
 4  Tell Bram to investigate the scratching sound.
 5  Signal Bram to wait; check the bones for clues.
 6  Instruct Bram to investigate the noise
 7  Wait and see if anything stirs in the dark.
 8  Tell Bram to stop; search the guardroom for clues first
...
20  Retreat quietly, find your companions.
```

**The cause is positional.** `_build_options_instruction` says *"Vary the tone:
one cautious, one bold, one curious, one witty"* — and the model emits them in
exactly that order, every turn:

| Slot | Turn 2 | Turn 4 | Turn 6 |
|---|---|---|---|
| 0 cautious | "Check the dungeon's entrance for traps." | "Hold torch high, check for traps." | "Peer into the archway, looking for traps." |
| 1 bold | "March straight in — we came for treasure" | "Tell Bram to stop being a coward." | "Tell Bram and Silvaine to wait here. Enter alone" |
| 2 curious | "Ask Bram — why do you smell oil down here?" | "Tell Silvaine to find the source of the noise." | "Examine the bones and weapons on the floor." |
| 3 witty | "Whisper to Silvaine — 'Let's not die today, okay?'" | "Push ahead, ignoring the strange noises." | "Light a second torch from the first." |

So **slot 1 is the cautious option essentially always**, and cautious actions by
construction do not satisfy transition conditions like *"when the party moves
past the guardroom and deeper into the dungeon."*

Then it compounds. A scene that never resolves gives the DM nothing to advance
toward, so it stops offering forward options at all — 2 of 20 turns under
`always-first` versus 7 of 20 under `random-choice`. The stall is
self-reinforcing, which is why random got a whole beat further despite choosing
blindly.

This matters beyond the harness: a real player who habitually clicks the top
option gets a permanently cautious game that never moves. Cheapest fix is to
shuffle the validated options before returning them in `run_phase3`, so slot
position carries no meaning. Worth doing regardless of what else changes, since
it costs nothing and removes a positional bias the UI can't see.

Neither mode reached the ending inside 20 turns. Both were otherwise clean —
0 errors, 0 fallbacks, 0 validation failures, 0 blank messages.

Findings 3 and 8 are two faces of the same thing: the Director advances on
actions that don't meet the condition, *and* the DM stops offering actions that
would. Worth tackling together — and re-running `always-first` afterwards, since
it's the sharpest single measure of whether the options actually go anywhere.

Re-run after each change and diff `report.json` — the counters block is a stable
schema built for exactly that.

## Method notes

- Dice never rolled in `trap-and-surrender`: a `jump_to` step produces no options,
  and the harness only looked at the immediately preceding entry for an offered
  roll. Fixed (`test_offered_dice_survives_an_intervening_jump_step`), so the
  trap will actually be rolled for next run.
- The headline table is the **pre-fix** pass, so the findings are all traceable
  to one run set. Finding 1 carries its own post-fix comparison
  (`runs/20260806-205420-dutiful`).
- One turn is ~6 LLM calls and 20–40s, rising as the transcript grows. A full
  `dutiful` run is about 5–6 minutes.
